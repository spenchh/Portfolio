FPGA-Based
Field-Oriented Control

A motor-control accelerator on an Arty Zynq-7000 SoC: a fully pipelined Q1.15 current loop in FPGA fabric that takes raw three-phase ADC samples to complementary center-aligned PWM, with the protection path implemented in hardware rather than software.

Platform
Arty Zynq-7000 SoC
Languages
Verilog and SystemVerilog RTL, MATLAB, Python
Datapath
12-bit ADC in, 16-bit Q1.15 signed, 24-bit scale
Status
Active research

The control loop

The current loop is a valid-chained pipeline. Each stage carries its own *_valid strobe, so a sample propagates through the datapath without a central scheduler and every stage knows precisely when its input is real.

  • ADC scaling converts raw counts to signed current, with per-phase offset subtraction and a 24-bit scale coefficient.
  • Clarke and Park transforms take three-phase currents into the rotating d-q frame.
  • Two PI regulators, one per axis, with clamped integrators for anti-windup.
  • Inverse Park returns the voltage command to the stationary frame.
  • Alpha-beta to duty conversion produces the three phase duties.

Fixed-point arithmetic

Everything runs in Q1.15. At each multiply the product widens to full precision, shifts back by fifteen fractional bits, and then clamps to the 16-bit range rather than wrapping. Wrapping in a motor controller means a sign flip in a torque command, so saturation is a safety property, not a numerical nicety.

The bounds are sign-extended to the product width before comparison, so a value that overflows 16 bits is compared honestly rather than after it has already wrapped. Every stage in the loop clamps this way.

Angle resolution

Sine and cosine come from a quarter-wave lookup table. A 16-bit electrical angle is split so the top two bits select the quadrant and the next six index a 64-entry quarter table; the cosine is read from the same table using a mirrored index. One quarter period of storage covers the full circle.

Modulation and deadtime

A center-aligned counter drives complementary high and low outputs on each phase, separated by a programmable non-overlap interval. The module exposes a configuration_error output that rejects any period and deadtime combination where the high and low sides could conduct simultaneously. The design refuses to run a configuration that could shoot through.

Two deadtimes have to fit inside one period, or the high and low sides of a leg could conduct together. That condition gates active, so an invalid configuration cannot drive the outputs at all — the check is structural, not a runtime warning.

Protection in fabric

Over-current, phase-imbalance, and bus and phase voltage monitors feed a latching disable controller. When any monitor trips, PWM is gated immediately and the fault is held until an explicit clear, with a status code identifying the cause. The protection path does not depend on software being alive.

Verification

Each block has a self-checking testbench that asserts on failure rather than printing waveforms for a human to read. Directed tests confirm that high and low pairs never overlap, that an inhibit truly shuts the outputs off, and that an invalid duty raises the configuration error. A MATLAB fixed-point model serves as the numerical reference.

Source. Thirteen RTL modules under fpga/rtl/, with self-checking testbenches alongside them, plus the MATLAB fixed-point models and the PCB work.
