Stateful FPGA
Datapath Research

I am researching how to discover and reduce latency in stateful FPGA datapaths with a collaborator. We are evaluating two potential directions: performance-guided on-chip fuzzing and live relocation of symbol state between memory banks.

Current stage. We are reviewing existing work, identifying a specific contribution, and choosing an experimental workload. Both topics are candidates; neither has a demonstrated research result yet.

Performance-guided on-chip fuzzing

I am exploring a hardware tester that generates valid event sequences, observes a datapath's queues and stalls, and changes its inputs to search for unusually high latency. The question is which feedback signals and mutation methods discover difficult cases most effectively within a limited hardware budget.

One candidate comparison is dependency-stall feedback versus queue-occupancy feedback alone. We would compare against random testing and existing feedback approaches under matched traffic constraints, measuring discovered latency, search effort, and tester resource usage.

On-chip fuzzing already exists. The contribution would need to be a particular search mechanism with a measured benefit over those baselines.

Live relocation of symbol state

The second direction is an FPGA state engine that detects memory-bank contention and moves selected symbols' data to less busy banks while updates continue arriving. I am investigating how a migration protocol and decision policy could preserve update order while reducing latency enough to repay the migration overhead.

We would measure buffering requirements, migration cost, FPGA resources, timing, and latency against static banking and simpler alternatives. Before committing, we need a workload with a meaningful memory bottleneck and a limitation that existing approaches handle poorly.

Development foundation

I have paused the original tick-to-trade build while we establish the research question. The earlier repository contains synthetic quote generation and initial decoder work. My separate stream stress tester currently implements a synchronous FIFO with an initial cocotb write/read check; traffic generation and fault injection are planned. These are development foundations for exploring stateful streaming hardware.
