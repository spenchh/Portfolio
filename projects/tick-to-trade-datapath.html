10GbE FPGA
Tick-to-Trade Datapath

A simulation-first FPGA datapath for low-latency market-data processing and order-decision logic. The trading workload is a forcing function for the real subject: deterministic networking, streaming packet parsing, fixed-point decision logic, and risk checks enforced in hardware rather than software.

Stack
SystemVerilog, Python, cocotb, C++20
Focus
10GbE, UDP/IP, streaming parsers, risk gating
Method
Simulation-first, reference model and scoreboard
Status
Active development

Status. This project is in active development. No latency has been measured, no timing has been closed, nothing has run on hardware, and nothing is connected to any live or production trading system. The evidence listed at the bottom of this page consists of targets, not results.

Why this workload

Market data is one of the most demanding latency targets available to study, which makes it a useful forcing function. The engineering problems underneath are general: parse a protocol at line rate, keep a pipeline from stalling unpredictably, do arithmetic in fixed point inside fabric, and enforce an interlock that software cannot override. The same problems appear in radar and avionics front ends, robotics, industrial control, and network equipment.

The pipeline

  • 10GbE ingress. MAC and stream interface, framing.
  • UDP/IP parse. Header strip, filtering, checksum.
  • Market-data decode. Message framing and field extraction.
  • Symbol and book state. Per-symbol tracking with deterministic update behavior.
  • Decision logic. Fixed-point evaluation.
  • Risk gate. Hardware-enforced checks that no order may bypass.
  • Order and cancel encode. Message build and TX egress.

Stages are streaming and back-pressure aware. The structural rule is that no path reaches egress without passing the risk gate.

Verification

Python and cocotb drive the environment: packet generation for synthetic market data, golden-model comparison against a Python reference, randomized and constrained stimulus, scoreboard checking, and a harness for cycle-level latency accounting across stages.

Host tooling

C++20 tools handle replay, control, and logging, driving simulated market data into the design, configuring risk parameters, and collecting structured debug evidence from runs.

Evidence targets

Artifacts I am working toward, stated so the goalposts are explicit:

  • Self-checking test suite across the parse, decode, decision, and risk stages.
  • Synthesis and implementation timing reports.
  • Cycle-level tick-to-trade latency accounting, first in simulation.
  • Waveform and packet captures documenting correct and fault-path behavior.
  • Directed tests proving no order reaches egress while a risk condition is asserted.
  • Eventual bring-up on an FPGA with a 10GbE interface.
